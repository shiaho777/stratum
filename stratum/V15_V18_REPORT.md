# V15-V18 Version Iteration Comparison Report — 27B Model

## Test Environment
- Model: Qwen3.6-27B Q4_K_M (16GB GGUF)
- Machine: Apple M4 Pro, 24GB RAM
- Test: 1-8 token generation, prompt [1, 12968]

## Per-Version Improvement Analysis

### V15: Memory-safety fix
- **Problem**: `newBufferWithBytesNoCopy` registering the 16GB mmap → GPU wires all physical pages = implicit mlock
- **Fix**: ephemeral `newBufferWithBytes` (copy semantics), no mmap-page wiring
- **Cost**: 8% slower (5.13s vs 4.74s), but memory drops from 6.7GB to 102MB
- **Finding**: GPU ephemeral is slower than CPU under SSD-I/O bottleneck (copy overhead > compute savings)

### V16: KV-cache out-of-bounds fix
- **Bug**: GPU KV cache hardcoded to 8 slabs; 27B has 16 full-attn layers → slots 8-15 out of bounds → NaN
- **Fix**: allocate 32 slabs
- **Result**: full_attn GPU goes from NaN to bit-exact (argmax=16, 25)
- **Finding**: GPU ephemeral still slower than CPU (7.45s vs 5.13s), but infrastructure fix paves the way for future GPU optimization

### V17: n-gram spec decode + MTP validation
- **Added**: Qwen3.5 n-gram spec decode (`STRATUM_NGRAM_SPEC=K`)
  - Zero draft-forward overhead; drafts generated by matching token-history n-grams
  - SSM state save/restore supports rejection rollback
- **Validated**: MTP chain spec K=7 reaches 4.00 tok/main_forward
- **Finding**: n-gram matches poorly on creative text (needs repetitive text); MTP drafts are higher quality

### V18: Page-cache management optimization
- **Changed**: `RELEASE_BEHIND` 2→0, `PREFETCH_AHEAD` 4→1
- **Rationale**: letting the OS LRU manage page cache is smarter than manual `MADV_DONTNEED`
- **Effect**: second token 14% faster (4.93s vs 5.73s), spec decode 16% faster

## Bottleneck Analysis

### Current bottleneck: SSD I/O
- 16GB model / 3GB/s SSD = 5.3s/token (I/O floor)
- Compute is only 35% (matmul 1.78s); I/O waiting is 65% (other 3.44s)
- GPU cannot solve the I/O bottleneck — weights still must be read from SSD into page cache

### Spec decode is the best speedup so far
- B=8 batched forward reads weights once, serves 4+ tokens
- MTP draft accept rate: 71% (K=7 first step 5/7 accepted)
- Effective speed 0.40 tok/s = 2.1x speedup

## Next-Version Direction (V19+)

1. **Raise MTP draft accept rate**: larger draft vocab, better tree structure
2. **Batched-forward compute optimization**: B=8 SSM recursion is serial; parallelizable
3. **Full_attn GPU optimization**: reduce ephemeral-copy overhead (chunked staging)
4. **Multi-sequence parallelism**: run several independent sequences concurrently, reusing weights
